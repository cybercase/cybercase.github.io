# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal blog/homepage (stefano.brilli.me) built with Next.js 16 (Pages Router, Turbopack) and React 19 as a **fully static export** (`output: "export"`, `trailingSlash: true` in `next.config.js`). There is no server runtime: no API routes, ISR, middleware, or anything else that needs a Node server at request time.

## Commands

- `npm run dev`: dev server on http://localhost:3000 (the RSS feed is not generated in dev)
- `npm run build`: static export to `out/`; the `postbuild` script then writes `out/feed.rss`
- `npm run lint`: ESLint 9 flat config (`eslint.config.mjs`: `eslint-config-next` core-web-vitals + typescript)
- `npx tsc --noEmit`: type-check. Run it after a build, because `next-env.d.ts` is generated by Next and gitignored.
- Formatting: Prettier 3 (`.prettierrc`: 2 spaces, semicolons, `es5` trailing commas). Posts in `posts/` are not formatted.

There is no test suite. Check changes by building and comparing the generated HTML in `out/`. Use Node 24 (`.nvmrc`). A husky 9 pre-commit hook runs lint-staged: ESLint on staged `js/mjs/ts/tsx` files and `prettier --check` on `js/mjs/ts/tsx/css/scss/json`.

## Deployment

`.github/workflows/deploy.yml` runs lint, build and tsc on every push and PR, and deploys `out/` to GitHub Pages on pushes to `main`. There is no local deploy script.

## Architecture

**Content pipeline.** Blog posts are Markdown files in `posts/`, with YAML front matter parsed by `gray-matter`. The filename (without `.md`) is the slug, served at `/blog/<slug>/`. `lib/api.ts` reads `posts/` and returns only the requested fields, with posts sorted by `date`, newest first. The front-matter fields are typed by `PostType` and listed in `postMetaFields`, both in `lib/constants.ts`. To add a field, update both. Pages should request only the fields they render, because everything returned from `getStaticProps` is serialized into the page.

**Build-only and browser-safe modules.** `lib/markdown.ts` (unified pipeline) and `lib/feed.ts` (RSS) must only be imported from `getStaticProps` or `scripts/`. Importing them into component code ships them to the browser. `lib/url.ts` is browser-safe.

**Markdown rendering.** `markdownToHtml` in `lib/markdown.ts` uses remark-gfm, smartypants and remark-math. Only `$$` is math, and single-line `$$…$$` renders inline. Then rehype-highlight (with `detect: true`, since most posts use unlabeled indented code blocks), rehype-katex, and raw HTML passthrough. rehype-katex reports invalid LaTeX as messages; `markdownToHtml` turns these into an error so the build fails. KaTeX is pinned to 0.19 with an npm `overrides` entry, and its CSS is imported from the same package in `_app.tsx`, so the class names always match.

**RSS.** `scripts/build-feed.ts` (run with tsx as `postbuild`) uses `getAllPosts` and `generateRSSFeed` to write `out/feed.rss`. The feed's `updated` date is the newest post's date, so the output is deterministic.

**Layouts.** Pages use a per-page layout pattern: `NextPageWithLayout` in `lib/constants.ts` has a `getLayout(page, props)` function, which `pages/_app.tsx` calls. Each page wraps itself in `BaseLayout` and passes in a `SiteHeader`, whose cover props come from post front matter or are set by the page. `coverCaption` is accepted but not rendered.

**Styling.** Global SCSS partials in `styles/` use the Sass module system (`@use`, not `@import`) and are loaded through `styles/main.scss` in `_app.tsx`. A partial that uses mixins, functions or placeholders from another partial must `@use` it. Fonts (Merriweather, Roboto, Ubuntu Mono) are self-hosted via `next/font/google` in `_app.tsx`, which also defines the `--font-serif`, `--font-sans` and `--font-monospace` CSS variables that the SCSS uses.

## Notes

- `baseUrl` in `lib/constants.ts` is used to build absolute OG and RSS URLs.
- Images live in `public/images/`, and posts reference them as `/images/...`.
- `.git-blame-ignore-revs` lists formatting-only commits.
